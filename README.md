# סטודיו מראה טבעי

אפליקציית MVP בעברית (RTL) להדמיית טיפוח טבעי, מדריך ביצוע, מעבדת Benchmark עיוורת, ניקוד וכיול כללים.

## דרישות

- Node.js 20 ומעלה
- מפתח Gemini API פעיל
- מודל ניתוח, מודל יצירת/עריכת תמונות ומודל שיפוט שזמינים בפרויקט Google AI שלך

## התקנה והרצה מקומית

```bash
npm install
cp .env.example .env
```

פתח את `.env`, הוסף `GEMINI_API_KEY` והגדר שמות מודלים שזמינים בחשבון שלך.

```bash
npm run dev
```

פתח את כתובת Vite שמופיעה בטרמינל (בדרך כלל `http://localhost:5173`).

## פריסה ל-GitHub

1. צור Repository חדש ב-GitHub.
2. חלץ את קובצי הפרויקט והעלה אותם ל-repository.
3. **לעולם אל תעלה את `.env` או מפתח API ל-GitHub.** הקובץ `.gitignore` כבר מחריג את `.env`.
4. כדי לפרוס, השתמש בשירות Node.js שתומך בשרת Express. הוסף שם את `GEMINI_API_KEY` ואת משתני המודלים כ-Secrets/Environment Variables.
5. ב-GitHub אפשר להפעיל Actions לבדיקות ובנייה; GitHub Pages לבדו אינו מתאים לפרויקט הזה כי נדרש שרת Express לשמירת מפתח ה-API.

## מודלים

ברירות המחדל משתמשות במודל `gemini-3.8-flash` לניתוח ולשיפוט.
- `gemini-3.8-flash` לניתוח ולשיפוט.
- מודל עריכת התמונה מוגדר בנפרד באמצעות `GEMINI_IMAGE_MODEL`.

יש לוודא שמודל עריכת התמונה זמין ותומך בהחזרת תמונה (`responseModalities: ["IMAGE", "TEXT"]`). אם הוא אינו זמין, השרת יחזיר שגיאה ולא ייצור הדמיה.

## ארכיטקטורה

- `src/` — React + TypeScript + CSS, ממשק RTL.
- `src/db.ts` — IndexedDB מקומי להיסטוריה, מקרי בוחן וכללי כיול.
- `server/index.ts` — Express וקריאות Gemini API בצד השרת בלבד.
- `/api/glowup/generate` — ניתוח ואז יצירת תמונה. מקבל תמונת מקור וכללי כיול פעילים.
- `/api/benchmark/evaluate` — שיפוט של שלוש תמונות אחרי יצירת התחזית.
- `/api/benchmark/calibrate` — יצירת כללים מדוגמאות זהב.

## גבול הבדיקה העיוורת

בזרימת הבדיקה, `/api/glowup/generate` מקבל **רק את תמונת הלפני**. תמונת ה"אחרי האמיתי" נשארת בדפדפן עד שהתחזית חזרה, ורק אז נשלחת ל-`/api/benchmark/evaluate`. זהו מנגנון עיוור ברמת זרימת האפליקציה, לא הבטחה קריפטוגרפית נגד שינוי קוד לקוח.

## פרטיות ואבטחה

- התמונות נשמרות ב-IndexedDB של הדפדפן הנוכחי.
- בזמן יצירת הדמיה או שיפוט, התמונות נשלחות ל-Gemini דרך שרת האפליקציה. לכן אין לתאר את המערכת כ"אחסון מקומי בלבד" או כעיבוד מקומי לחלוטין.
- הוסף אימות משתמש, הגבלת קצב, מדיניות שמירת נתונים, HTTPS והגבלת גודל בקשות לפני שימוש ציבורי.
- הוסף `GEMINI_API_KEY` רק בסביבת השרת. אין להוסיף אותו לקוד React או למשתני `VITE_*`.

## מגבלות MVP

- תמונות דוגמה מובנות, drag-and-drop מלא, בדיקות אוטומטיות וניהול הרשאות עדיין אינם כלולים.
- הסליידר הבסיסי כלול; מומלץ לבדוק אותו בדפדפנים ובמסכים שונים.
- ציון AI הוא הערכה ולא מדד אובייקטיבי. יש להשתמש גם בביקורת אנושית.


## פריסה ב-Render

הפרויקט כולל `render.yaml`. ב-Render בחר **New → Blueprint** וחבר את המאגר הזה. Render ישתמש בפקודות:

- Build: `npm install && npm run build`
- Start: `npm start`

במסך Environment של השירות יש להגדיר את `GEMINI_API_KEY` כמפתח סודי. אפשר להגדיר שם גם את מזהי המודלים `GEMINI_ANALYSIS_MODEL`, `GEMINI_IMAGE_MODEL` ו-`GEMINI_JUDGE_MODEL` בהתאם למודלים הזמינים בפרויקט Google AI שלך. אין להעלות קובץ `.env` או מפתח API ל-GitHub.

השרת מגיש את ממשק Vite מתוך `dist/` ואת נתיבי ה-API מאותו origin. בדיקת בריאות זמינה ב-`/api/health`.
